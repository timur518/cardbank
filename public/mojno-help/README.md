# Консультант МОЖНО

PHP 8.2+, Guzzle 7.10.0, Dotenv 5.6.3. Общее ядро отвечает через OpenAI Chat Completions, Telegram работает через long polling, сайт — через JSON endpoint. Смена канала не требует изменения промпта. Версии зависимостей сохранены из исходного проекта; каталог vendor включён.

## Запуск

1. Распаковать проект в отдельную директорию. Остановить предыдущий процесс Telegram перед заменой. Старую историю и старую базу знаний не переносить.
2. Скопировать `.env.example` в `.env`. Заполнить `OPENAI_API_KEY`; для Telegram также `TELEGRAM_BOT_TOKEN`. Рабочие ключи и старые переписки в архив не включены.
3. PHP должен иметь PDO SQLite, SQLite 3.35+ (для RETURNING), JSON, mbstring или поставляемый polyfill, HTTPS через curl или streams. Директория `storage` должна быть доступна на запись PHP-процессу и пользователю Telegram. При разных пользователях настроить общую группу и umask 0007, не использовать chmod 777.
4. Запустить `php tests/smoke.php` и затем `php bot.php`. Для фонового запуска: `bash start.sh`. Путь к PHP можно задать через `PHP_BIN=/opt/php83/bin/php bash start.sh`. Для постоянной работы рекомендуется systemd/Supervisor, команда — `php /полный/путь/mojno-help/bot.php`.
5. Для сайта указать **document root строго на `mojno-help/public`**. Корень проекта, `.env`, `storage` и исходники не должны быть доступны по HTTP. Настроить PHP-FPM для `chat.php`, HTTPS и таймаут прокси не менее 65 секунд.
6. `WEB_ORIGIN` — точный origin, с которого загружается чат: например `https://mojno.cc` или `https://chat.mojno.cc`, без пути и завершающего слеша. `SESSION_SECURE=1` для HTTPS. Telegram работает без настройки WEB_ORIGIN.

Для локальной проверки: `WEB_ORIGIN=http://127.0.0.1:8080` и `SESSION_SECURE=0` в `.env`, затем `php -S 127.0.0.1:8080 -t public`. Открыть этот адрес. Встроенный сервер PHP предназначен только для разработки.

## Чат на сайте

Готовая страница находится в `public/index.html`. Можно разместить её на том же origin по пути `/help/` и встроить iframe, либо подключить свой интерфейс к `chat.php`. Междоменные запросы напрямую не разрешены; для другого домена использовать серверный reverse proxy. Вариант с iframe на отдельном домене может зависеть от ограничений браузера на сторонние cookies; предпочтителен тот же origin.

Пример встраивания страницы на том же сайте:

```html
<!-- Встраивается интерфейс консультанта МОЖНО. -->
<iframe src="/help/" title="Консультант МОЖНО" style="width:100%;height:720px;border:0"></iframe>
```

API:
- `GET chat.php` — создать серверную сессию и получить `csrf_token`.
- `POST chat.php` с JSON `{"message":"Как оплатить подписку?"}`, заголовком `X-CSRF-Token` и cookie сессии — ответ `reply`, `handoff`, `support_url`.
- `POST chat.php` с JSON `{"action":"clear"}` — очистить историю и начать новый диалог.
- Ошибки: 400/422 — ввод, 403 — origin/CSRF, 413 — размер, 429 — лимит, 503 — инфраструктура. При недоступности модели возвращается безопасный текст с поддержкой.

`handoff=true` означает предложенный переход в поддержку, **не отправку заявки и не подключение оператора**. Ссылка: https://t.me/mojno_support. Сообщения поддержки автоматически никуда не отправляются.

## Промпт и знания

- `prompt.md` — роль, общие знания модели, консультации, нейтральность, агрессия, тупиковые диалоги и эскалация.
- `knowledge.md` — проверенные условия МОЖНО. Перед запуском добавить актуальные тарифы, лимиты, сроки, порядок покупки и ограничения. Они отсутствовали в исходных материалах и намеренно не выдуманы.
- `knowledge.php` — объединяет эти файлы; изменения применяются при следующем запросе без перезапуска Telegram.
- `src/Consultant.php` — единый метод `reply($conversation, $message)` для новых адаптеров. Идентификатор диалога должен формироваться доверенным сервером, а не приниматься от клиента.

Модель может отвечать на общие вопросы вне базы знаний. Онлайн-поиск и проверка платежей не подключены. Модель по умолчанию сохранена из исходной конфигурации: `gpt-4o-mini`; меняется через OPENAI_MODEL на совместимую с Chat Completions модель.

## Эксплуатация

Истории Telegram разделяются по чату, теме и отправителю; сайт использует случайный идентификатор серверной сессии. Истории между каналами не объединяются. `/clear` очищает текущий диалог, `/support` даёт ссылку на поддержку. В группах бот реагирует на упоминание или ответ ему; ответ виден участникам группы.

SQLite хранит не более MAX_HISTORY_MESSAGES сообщений на диалог, данные старше HISTORY_TTL_DAYS удаляются при обработке запросов. Для удаления без трафика добавить ежедневный cron: `php /полный/путь/mojno-help/prune.php`. Файлы блокировок не содержат сообщений; удалять их следует только при остановленных процессах. Логи не содержат текста переписки или исключений с ключами. Настроить ротацию storage/bot.log.

Веб-чат ограничивает частоту на сессию, IP и весь веб-канал. За reverse proxy REMOTE_ADDR должен корректно выставляться доверенным сервером; заголовки клиента код самостоятельно не считает доверенными. Для публичного сайта дополнительно настроить лимиты на reverse proxy/WAF и бюджет OpenAI. Анонимные лимиты не заменяют защиту от распределённого злоупотребления.

Тексты и ограниченная история диалога передаются в OpenAI API. `store=false` не является обещанием полного отсутствия хранения у провайдера. Учесть фактический поток данных в документах сервиса и уведомлении пользователей; не просить реквизиты и секреты. База SQLite не зашифрована этим приложением: доступ ограничивается правами сервера.

Telegram offset сохраняется между перезапусками. При ошибке отправки запись журналируется и очередь продвигается, автоматической гарантированной повторной доставки нет. При аварии между отправкой и записью offset возможен повтор ответа. Для больших нагрузок потребуется очередь и отдельные воркеры; текущий Telegram-адаптер обрабатывает запросы последовательно.

## Проверка

`php tests/smoke.php` проверяет изоляцию истории, её ограничение и очистку, rate limit, системный промпт, успешный ответ, прямой запрос оператора, пустой ответ API, ошибку API и пустой ввод. Используется Guzzle MockHandler, реальные ключи не нужны.

Перед публичным запуском проверить диалоги с выбранной моделью: «Что такое 3-D Secure?», «Сколько стоит выпуск?», «Вы лучший сервис?», агрессивная жалоба, «Уже пробовал, не помогло», «Деньги списаны», «Нужен оператор». Промпт направляет поведение модели, но не даёт математической гарантии каждого ответа.

Документация интеграций: https://developers.openai.com/api/reference/resources/chat и https://core.telegram.org/bots/api.

Проверки при подготовке архива: синтаксис JavaScript и Bash, корректность JSON, целостность ZIP и отсутствие прежнего бренда пройдены. PHP отсутствовал в среде подготовки, поэтому PHP lint, smoke-тесты и запросы к реальным API не запускались. Перед развёртыванием выполнить PHP-проверки на сервере.
